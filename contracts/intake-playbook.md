# 采料问卷与人群 playbook

> 目标：解决"没什么可写的人"的素材荒。**没实习 ≠ 没料**——课程设计、大作业、毕设、
> 竞赛、社团、兼职、自学项目都是合法素材。本文件指导 agent 系统性地把用户的日常
> 翻译成可核实的简历原料。

## 一、采料问卷（首次建库 / 素材不足时逐项问）

按**已有的往下问、没有的直接跳过**，不要机械问完。每问到一条，立刻判断它属于
`profile.yaml` 的哪个字段（`education` / `experience` / `projects` / `awards` /
`open_source` / `skills`），并问清时间、规模、结果。

### 1. 教育经历（几乎人人有，必问）

- 学校、学历、专业、学院、起止时间
- **主修课程**：挑 5–8 门与目标岗位相关的（投 AI 就写机器学习/NLP，投后端就写操作系统/数据库）
- 在校荣誉：奖学金、优秀学生、竞赛获奖（写清级别：校/省/国）

### 2. 项目经历（无实习者的核心素材区，逐项追问）

- **课程设计 / 大作业**：哪门课？做了什么系统？用了什么技术？几个人？你负责哪部分？
- **毕设 / 课程论文 / 实验**：题目？复现了什么？数据集？结果如何？
- **自学练手项目**：跟着教程做过的系统、开源项目 fork 改造、个人小工具（GitHub 仓库即可）
- **竞赛项目**：数学建模、ACM、大创、"互联网+"等——哪怕没拿奖，做过就有产出

> 关键追问：**"你在里面具体做了哪几件事？"** 把回答拆成 bullet，而不是写"参与了 XX 项目"。

### 3. 实习 / 工作经历（有就深挖，没有不硬凑）

- 公司、岗位、起止时间、部门
- 业务背景一句话；你负责的模块；量化结果（提升/降低/覆盖了多少）

### 4. 校园与社会实践（应届生常用填充项）

- 社团/学生会/班委：职务、组织过什么活动、规模（多少人参与）
- 兼职/志愿者/支教：内容、时长、成果
- 这些不直接相关，但能证明**沟通、组织、责任心**，放在靠后章节

### 5. 技能（结合证据问，不许空口"精通"）

- 语言/框架/工具：每个技能追问**"在哪用过？什么项目里？"**——有项目佐证才算掌握
- 证书：英语四六级/托福雅思、计算机等级、专业认证

### 6. 开源与个人品牌（AI/开发岗加分）

- GitHub/博客/技术社区账号；有无 star 的项目、有无技术文章

## 二、人群 playbook（按画像调结构侧重）

### A. 应届生 · 无实习

- **结构**：教育经历 → 项目经历（课程设计+自学项目，放最前最重）→ 技能 → 校园经历 → 自我评价
- **关键策略**：把课程设计/毕设当"项目"写，突出**做了什么系统、用了什么技术、解决了什么问题**
- **避坑**：不写"无实习经验"等自曝短板的话；用项目密度弥补实习空白

### B. 应届生 · 有实习

- **结构**：教育经历 → 实习经历 → 项目经历 → 技能
- **关键策略**：实习放重，量化结果优先；项目挑与 JD 最相关的 1–2 个

### C. 考研上岸 / 二战 gap

- **结构**：教育经历 → 项目/科研 → 技能 → 自我评价
- **关键策略**：gap 期不解释不回避；若有考研期间的技术积累（自学、开源、毕设）写进项目
- **避坑**：不主动提及"gap"，简历只呈现**有产出的事实**

### D. 转行者

- **结构**：技能（放前，对标 JD）→ 项目经历（转行方向的练手项目，哪怕小）→ 工作经历（原行业，提炼可迁移能力）→ 教育
- **关键策略**：用**新方向的项目**证明学习能力；原行业经历强调"跨领域理解/项目管理/沟通"等可迁移技能
- **避坑**：不堆砌原行业技术栈关键词；JD 关键词对齐（见 `jd-alignment.md`）在此人群最关键

## 三、从"日常"到"bullet"的翻译示例

| 用户原话（粗糙） | 改写后（可核实、有动作） |
|---|---|
| "帮老师做过一个网站" | 用 Vue + Spring Boot 开发实验室设备管理网站，实现设备台账与借用登记 |
| "本科做过课设" | 数据库课程设计：设计图书借阅库表结构，实现 6 张表的 CRUD 与借阅超期统计 |
| "会 Python" | Python 课程大作业：用 pandas 清理 10 万行销售数据，产出月度趋势图表 |
| "在社团干过" | 担任学生会宣传部部长，组织校级迎新晚会（参与 500+ 人），统筹 8 人宣传组 |
| "跟视频做过一个小项目" | 跟随教程实现待办事项 Web 应用（React + FastAPI），自行增加标签分类与到期提醒 |

**共同点**：动作动词 + 技术栈 + 具体产出 + 可验证的规模/结果。所有内容必须来自用户实际
做过的事，改写**不等于编造**。

## 四、素材不足时的兜底顺序

当用户确实"没啥可写"时，按此顺序挖掘：

1. 毕设/课程论文（几乎人人有）
2. 任意一门课的大作业（问"哪门课做过东西？"）
3. 自学项目（"跟着做过什么？"哪怕是 todo app）
4. 技能单点（"哪个技术你敢在简历上被问？"——有底气的才写）
5. 以上都挖不出来：如实告诉用户素材太少，建议先做 1 个练手项目再回来，不要编造填充
